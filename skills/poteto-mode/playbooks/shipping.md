### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then keep your hands off the queue.** For "land the stack", "ship it", "enable merge when ready", or the second half of a stack that **Babysit** already drove green.

This is the half after `./babysit.md`. Babysit makes a chain mergeable. Shipping decides what is safe to merge. Graphite is optional; ordinary git and `gh` are the fallback.

1. **Verify every PR independently before arming anything.** Run one independent verifier subagent per PR. Use a named agent when it needs distinct tools, permissions, prompts, or model configuration. Each verifier compares parent to head on the real surface using the project tests and the UI, CLI, shell, diagnostics, screenshot, or MCP tools actually available. It returns `PASS`, `PASS+NOTES`, or `FAIL` and records that verdict on its PR so the evidence outlives chat. CI green and approving automation are inputs, not verdicts.
2. **Land only the contiguous verified run rooted at the bottom.** Walk upward from the lowest unmerged PR and stop at the first one without a passing verdict. A verified PR above an unverified one is not landable because merging it pulls the gap underneath it. Report the ceiling as a PR number and state what breaks the chain.
3. **Re-check that verdicts still describe the code.** Updating or restacking can rewrite SHAs and invalidate verdicts without changing check names. Compare `git patch-id` at the verdict SHA with the current head when possible, and re-verify every changed patch.
4. **Choose the repository's merge mechanism.** If Graphite is installed and already manages the stack, arm merge-when-ready through Graphite and verify its own state. Otherwise use ordinary `gh pr merge` in dependency order, waiting for each parent to land and each child base to retarget before the next merge. Never introduce Graphite solely for this playbook.
5. **Never enable GitHub auto-merge across an unprotected parent chain.** A child that targets an unprotected parent may merge immediately and collapse review granularity. With the `gh` fallback, merge one verified PR at a time from the root and verify the new base before continuing.
6. **Confirm through the mechanism that owns the queue.** Do not infer Graphite merge-when-ready from GitHub's `autoMergeRequest`. Do not infer a `gh` merge from stale local refs. Query Graphite when it owns the stack, or query GitHub and fetch refs when `gh` owns it.
7. **Once the queue drains, stop mutating topology.** No restack, speculative push, or base retarget unless a diagnosed blocker requires it. Independent work gets re-parented onto trunk and shipped separately.
8. **Watch only while an execution surface is active.** Run `bun <poteto-mode-dir>/scripts/watch-pr/watch-pr` in queued mode over the verified run, resolving `<poteto-mode-dir>` from the installed skill location. In an attached session, supervise it until `COMPLETE` or the declared checkpoint. For detached continuation, use a Kiro cloud session or repository automation. A local chat that closes cannot continue watching.
9. **Stop at the ceiling.** Report what landed, the next unverified PR, and what verifying it requires. Extending the run is a new pass through step 1.

**Reply:** the verified run and ceiling, each PR's verdict and evidence, the merge mechanism used and how it was confirmed, what landed, and what the next gap needs.
